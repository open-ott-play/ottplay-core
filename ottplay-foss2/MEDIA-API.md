# Media API and verification boundary

`OTT2.require("media").create({ video, environment, options, onEvent })` creates one isolated media session. `video` is an HTML5 media element, `environment` supplies timers, optional XMLHttpRequest and upstream Hls/Shaka/mpegts engines. In the shipped application, `environment.OTT2Vendors` holds the lazily accepted engine references; late rejected vendor globals do not change capabilities. `environment.OTT2VendorLoader` supplies gated, deduplicated on-demand loads; the catalog does not fetch optional engines. `options.device` accepts detected profile IDs, including `lg/webos` and `lg/netcast`; an LG UA is also recognized. Application state, DOM controls, providers and device key maps do not live in this module.

The core requires ES5 and an HTML5 media element. It does not require `Promise`, `Map`, `Set`, `URL`, `Object.assign`, `Object.entries`, `Array.from`, or `Array.prototype.includes`. Vendored MSE engines receive the shared language polyfills before evaluation, then pass separate native capability gates. HLS uses `/src/hls-worker.js` only when the pre-polyfill capability report confirms native binary and Worker APIs. The worker imports and verifies its own bootstrap before the HLS payload; reported asynchronous worker errors disable workers on subsequent loads in that media instance. A synchronous Worker constructor failure is handled inline by upstream Hls.js and may be attempted again by a later instance. ES5 syntax alone is not proof of those APIs or codecs.

## Session and progress

- `load(channel, selection)`, `play()`, `pause()`, `stop()`, `destroy()` control the session. A channel requires `url` and should specify `kind: "live"` or `kind: "vod"`. HTTP(S) and blob stream URLs are allowed. The optional selection is `{engine: "auto"|"native"|"hls.js"|"shaka"|"mpegts", format: "auto"|"hls"|"dash"|"mpegts"|"flv"|"file"}`; channel.engine/channel.format are also accepted. Declared MIME/type, URL extensions and query hints (output/format/container/type) identify streams before any probe.
- `suspend(intent)` releases host resources while retaining the channel, VOD/DVR position and pause intent; `getState().suspended` reports this state. `resume()` reattaches only a previously active unpaused session. A paused session stays detached until explicit Play. Optional `{paused: boolean}` supplies authoritative application intent when a TV emits native Pause before visibility changes; omitting it preserves media pause state. Stop, new load and destroy invalidate suspension. The app uses this lifecycle only for TV profiles and rechecks authorization on foreground.
- `seek(seconds)` accepts only finite positions when a usable seek range is available. It clamps to the available VOD duration or live DVR window and snaps gaps to the closest available edge. Seeking does not clear the user's pause.
- `volume(value)` clamps to 0–1; `mute(boolean)` controls mute.
- `getState()` returns state, channel, position, duration, pause intent, a numeric `session` generation, retry count, backend, requested engine, detected format, requested format, detection reason, sanitized lastError, bounded fallback count, engine readiness, volume/mute, seek range, tracks, picture mode and PiP state. A missing seek range is `null`; its presence does not prove successful physical-device seeking.
- `capabilities()` reports available native HLS/DASH, gated Hls/Shaka/mpegts, selectable engine availability, currently exposed tracks, seek range, video geometry and detected PiP support. `nativeDeviceBridges` remains false: this distribution does not ship firmware-specific AVPlay, OIPF, gSTB or mobile bridge implementations.

Auto prefers LG native HLS (a typed `<source>` also covers extensionless HLS), and prefers Hls.js on Chrome/Chromium even when canPlayType claims native HLS. Other browsers retain native HLS preference when advertised. Shaka handles DASH and can be an HLS fallback. Raw MPEG-TS/FLV use the mpegts.js transmuxer when its actual streaming capability is present; `isSupported()` alone is insufficient for live streams. Engines still depend on device codecs and stream access.

For unknown URLs in Auto, a cancellable XHR reads response MIME or the first 4096 characters for HLS, DASH, TS packet sync, FLV or MP4 signatures. The request aborts as soon as identified, at a progress threshold of 64 KiB (network/browser chunk delivery may overshoot that threshold), or after four seconds. No whole live stream is intentionally buffered. CORS/probe failures fall back to native without blocking startup indefinitely; `detectReason` reports that boundary. A manual engine or stream format bypasses probing. No stream URL or response body is included in diagnostic fields.

`setEngine(value)` and `setFormat(value)` replace the current backend while retaining pause intent and a seekable position, applied after replacement metadata is available. VOD/archive uses absolute seconds; live uses distance from the new seekable edge. A temporarily rejected live seek retains the pending offset. The `session` generation advances on an adapter restart but remains stable through ordinary `pause()`/`play()`. They update preferences without starting a stopped or idle session. Manual engine selection never silently falls back: an unavailable engine reports `engine_unavailable`. Auto tries each compatible engine at most once on container/decoder/start failure, silent startup or a stalled media clock. Video verification requires positive video evidence and favors fresh decoded frames; old firmware uses dimensions/TrackList hints. Radio and unknown manifests do not become video failures merely because no video track is exposed. HLS media-error recovery/downshift is limited to one attempt per session; TV buffers are smaller. See the detailed bounds in [engine compatibility](docs/ENGINE-COMPATIBILITY.md). Recoverable Shaka errors leave recovery to the adapter while the no-progress watchdog stays bounded; critical errors use normal Auto fallback. Terminal VOD/archive errors retain position for explicit Play or engine retry. Intermediate engines cannot overwrite a pending DVR offset before exposing usable metadata. Stop, completed playback and a new stream discard restoration. Network retry remains bounded for live streams; VOD network failures do not restart the movie automatically. Pending adapter destruction finishes before a new adapter or source attaches to the same video element. Generation tokens cancel probes and late callbacks across load/stop/error/destroy.

LG platform behavior follows its [streaming specifications](https://webostv.developer.lge.com/develop/specifications/streaming-protocol-drm) and [media type documentation](https://webostv.developer.lge.com/develop/guides/mediaoption-parameter). MPEG-TS integration follows the [upstream API](https://github.com/xqq/mpegts.js/blob/master/docs/api.md). These document capability boundaries; they do not certify a particular TV or provider.

## Audio and subtitles

`listTracks()` returns `{ audio, subtitles, subtitlesOff }`. Each track has an opaque string `id`, `label`, `language` and `selected`. Treat IDs as valid only for the current session and latest track inventory. `selectAudio(id)` and `selectSubtitle(id)` select a track; `selectSubtitle("off")` disables subtitles. Methods return false when selection is unavailable or the ID is invalid.

The implementation supports native AudioTrackList/TextTrackList, Hls.js audio/subtitle tracks, and Shaka audio/text tracks. Native metadata/chapter tracks are excluded and are never disabled by subtitle selection. Shaka 5 uses `selectTextTrack(null)` for Off; an older separately supplied Shaka adapter with `setTextTrackVisibility` is also accommodated.

Listen for `tracks` events to refresh track choices. The application-level `playback-preferences` module stores language/label choices by source/channel, handles late tracks and explicit Off, and reapplies them when the session generation changes. The media module itself does not own persistent settings. An empty list means that the engine/browser has not exposed selectable tracks; it does not mean that the underlying file has no audio.

## Picture and PiP

- `setAspect("fit" | "fill" | "stretch" | "16:9" | "4:3")` updates the picture geometry. Fit preserves source ratio, Fill crops, Stretch fills the parent, and the two ratio settings constrain the picture rectangle.
- `setZoom(number)` accepts 0.5–3. Geometry uses explicit dimensions and margins when the parent can be measured, with `object-fit` as an additional modern-browser hint. The parent should clip overflow. Metadata and video/window resize events recompute dimensions. Destroy restores the original inline style.
- `enterPip()` requests standard browser or WebKit picture-in-picture. It should be called directly from a user action after media starts. True means that a request was dispatched, not that the platform accepted it; `pip` events and the snapshot report actual state.
- `exitPip()` exits this video's PiP. Stop, source change and destroy also close it. A canceled asynchronous entry closes its late window. Errors emit `piperror` and leave playback running.

Browser PiP is one floating playback window. Simultaneous channel preview, multiple decoders, firmware PiP and DRM are separate capabilities and are not claimed here.

## Events and tests

Alongside loading/playing/buffering/paused/suspended/stopped/ended/error, the module emits detecting, engine, enginefallback, recovery, metadata, timeupdate, volumechange, seek, tracks, geometry, pip and piperror. Notifications contain a fresh snapshot. Engine errors use stable codes and English fallback messages; the UI may localize them by code.

`node --test tests/test-media.cjs` verifies native operation without modern APIs, cancellation, bounded recovery, retained pause including native-control/OS pause, live DVR/gap seeking, native/HLS/Shaka tracks, legacy geometry, standard/WebKit PiP and asynchronous adapter teardown. `npm run check:es5` parses every shipped runtime script, including all vendors, with Acorn ECMAScript 5.

These are deterministic API/lifecycle tests. Actual TV firmware, codecs, audio decoders, encrypted content and native-device focus/input behavior need hardware checks. This module accepts an injected video/environment boundary so a future firmware integration can provide an explicitly tested media facade without global player state; it does not infer device support from a user-agent string.

`node tests/browser-media.cjs` is a separate real Chromium test, requiring FFmpeg on PATH (or `FFMPEG` set to its binary). It generates temporary H.264/AAC clips, starts the actual static server on an ephemeral loopback port, and exercises native HLS where available, forced Hls.js MSE, Shaka DASH with two audio languages, audio selection and paused seeking. It removes its server and generated files afterward.

`node tests/browser-engines.cjs` verifies the complete media module against generated extensionless HLS (both MIME and signature identification), MPEG-TS and FLV streams in Chromium. It requires decoded frames and advancing playback without engine or browser errors. It also switches a paused HLS session from Hls.js to Shaka at two seconds and checks that changing the engine after Stop does not start playback. The Shaka adapter supplies a saved start position to `load()` and waits until adapter readiness before applying any remaining seek, avoiding early-metadata position resets. This test creates and removes its own temporary FFmpeg media and loopback server.

The media browser suite also verifies native/Hls.js/Shaka host suspension: foreground keeps intentionally paused sessions detached, explicit Play restores the saved position, and previously playing sessions resume with decoded frames. These generated-media checks do not certify actual TV firmware.
