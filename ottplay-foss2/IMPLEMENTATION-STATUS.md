# OTT-play FOSS 2 implementation status

Version `0.6.0-beta.1`, 2026-09-18. See [beta release notes](docs/RELEASE-0.6.0-beta.1.md) for the resolved deep-audit findings and validation boundary. This is an independent ES5 application with a compact LG-oriented interface and working browser playback. English is the first-run and unknown-language default; Russian is selectable and persists across reloads. RobotoCondensed is the default local font. The original player's application code is not used.

This document distinguishes the delivered interface from the broader ecosystem requirements in [Technical specification](TECHNICAL-SPEC.md). ES5 parsing, remote profiles and physical hardware playback are separate checks.

## Implemented

### Interface, collections and local data

The compact layout normally shows 26 rows at 720p/1080p and 25 with desktop window-control space. Rows use one base-font em with unchanged text sizes and a single bottom separator. The right-hand programme panel starts automatic scrolling after 3 seconds, moves at 14 CSS pixels per second, waits 4 seconds at the bottom and returns to the beginning. Pointer interaction pauses it for 8 seconds. Hidden views, open dialogs, the sections menu and focused Info controls pause movement. The controller retains its reading position and timing across replacement DOM nodes, resets for a new programme and never changes channel focus or the media session.

Television, favorites, TV guide, nested video library, sources and settings are implemented. The TV list has aligned channel number/name and current-programme columns, targeting at least 20 visible rows at normal 720p/1080p text size. Channel count, filters and optional EPG status share the first heading, with no redundant column heading or separate Previous/Next row. The page counter sits in the heading and the top margin is reduced. Larger type and shorter windows reduce the row count; narrow portrait screens retain larger touch targets. Pagination bounds DOM size. Local RobotoCondensed and a system fallback remain available.

The sidebar is collapsed by default. The visible Menu button and remote Menu toggle it; Back closes it first and restores focus. Up at the first channel wraps to the last channel in the current filtered collection; Down at the last wraps to the first. This also applies to favorites and single-page lists. Menu followed by Up from the first sidebar section reaches the header controls. Full-row highlighting, modal focus isolation and a Latin/Cyrillic/URL keyboard support remote-only input. Up/Down move through channels; Left/Right and CH+/CH− page while retaining the row where possible and remain clamped at the ends.

Mouse/trackpad scrolling follows the nearest scrollable container. Channel/favorite/VOD pages and guide boundaries support wheel paging; long EPG descriptions, dialogs, inputs, settings, sidebar and playback controls expose native overflow. Standard wheel, old WebKit mousewheel and Gecko DOMMouseScroll events are supported without double processing. Zoom modifiers are left to the browser, and scrolling never starts another channel. Background EPG refresh retains scroll positions on the current page.

Clicking full-screen video opens the channel list and focuses the playing channel on its page. The same video continues in the preview. Clicking the preview expands the playing stream to the full application window. It keeps the current channel and pause state, and does not request native OS fullscreen. Clicking the expanded video returns to the list. Back/Resume returns to full viewing without reconnecting or changing pause state. Clicking a live channel or pressing OK starts it through the normal PIN check. Info opens channel actions and the full programme description. External names and descriptions are escaped text.

Named collections support creation, rename, deletion and item order. The channel editor changes name/group/order/visibility through local overrides, with restoration of hidden channels and original fields. Entire groups can be renamed. Source playlists are not rewritten. Long opaque IDs survive overrides, bookmarks and reminders.

Favorite episodes retain path IDs and names. After reload the provider resolves a fresh catalog path; stream URLs and portal tokens are not stored for that purpose. History supports deletion and VOD bookmarks, and playback has a sleep timer. Settings include English/Russian, six local font names and a system option, text size and three accent colors. All 11 original font resources are retained; Liberation remains the documented Roboto alias from the source assets.

Startup restore is enabled by default. The first validation of older settings enables it and records `startupVersion: 1`; a subsequent explicit opt-out in Preferences persists. Confirmed live playback immediately saves a separate `lastChannel` reference containing `sourceId`, `id` and available original provider `tvgId`, `tvgName`, `name` and `group` strings, each metadata field limited to 512 characters. Local name/group overrides do not replace the provider identity used for startup matching. Archive playback records its underlying channel for live playback on reopening. The record is independent of history and the currently browsed source, survives Stop and a later failed stream, and is removed when its source is deleted. Ordinary exports clear the reference with the sources; full exports retain it without adding resolved stream URLs, tokens or EPG snapshots.

Startup selects the source from that record and loads its current playlist. The exact channel ID has priority; if it has changed, an unambiguous provider TVG ID/name/group match within that source can recover the same channel after stream URLs rotate. Names retain quality and regional suffixes. Multiple recognized M3U copies may restore the same broadcast when they share the nonempty case-sensitive TVG ID, match the saved nonempty channel name and have identical raw metadata keys and JSON values except `id` and `url`. Startup selects the first equivalent copy in the current source order; differences in group, parental flags, catch-up or other playback attributes prevent this fallback. Ambiguous names without TVG identity and unnamed legacy variants remain rejected.

Older ID-only records can recover a name from the history entry with the same ID. A protected old ID transfers its PIN requirement to the matched refreshed ID before normal playback authorization. Existing installations without a saved channel retain exact-ID history fallback, including an available VOD bookmark; history-only entries cannot select a live channel by metadata after their old ID or source disappears; startup does not promise expansion of nested VOD catalogs. A missing or ambiguous broadcast leaves the list available. User actions cancel a pending startup restore, and source or playback failure consumes the attempt rather than rearming it. Opening the video view does not request DOM fullscreen.

### Installed desktop window

A local web app manifest supplies stable root identity/start URL/scope, 192/512-pixel icons, standalone fallback and an optional Window Controls Overlay display mode. Its CSS keeps video across the full client viewport, provides a transparent nonfocusable drag region only inside the browser's free title-bar rectangle, and places browsing content, dialogs and the on-screen keyboard below native buttons. The footer remains bounded in short windows. Fullscreen explicitly hides the drag region and clears the insets, then the windowed layout returns on exit. Ordinary browser/TV styles remain the fallback; no browser JavaScript, Service Worker, cache or startup-order change is introduced. The server exposes only the specified manifest/icon routes in addition to its existing asset allowlist.

An existing Chrome app can accept Review App Update → Update, close/reopen, and select Hide title bar; Show title bar restores the conventional bar. Retaining the existing origin and browser profile preserves sources, settings and the saved channel. The installed macOS app was updated without uninstalling or resetting data; other desktop implementations and native dragging require separate verification.

### Sources and EPG

- M3U/M3U8 supports URL, pasted text and files, relative URLs, groups, tvg-id, EPG URLs, time offsets and explicit catchup parameters.
- Xtream supports authentication, live/VOD categories and streams, series/seasons/episodes, playback resolution and bounded timeshift archives.
- Standard Stalker/Ministra supports handshake/profile, paged live catalogs, VOD categories/movies/seasons/episodes/files and create_link through the configured relay. Portal tokens and commands remain inside the provider session.
- XMLTV supports timezone-aware dates, channel matching, current/next, offsets, merging up to ten feeds with deterministic deduplication, filtering/paging, descriptions, supported archives and local reminders.

EPG selection follows explicit user URLs, playlist URLs, then the built-in `https://cdn.epg.one/epg2.xml.gz` fallback. Clearing a custom XMLTV field restores automatic selection. Visible status distinguishes loading, matched/current channel counts, no matches, stale dates and source errors.

Exact tvg-id matching precedes unique tvg-name/name matching. A final unambiguous alias may strip standalone HD/FHD/UHD/4K tokens without removing region, language or time offsets. Different IDs with the same alias are not merged. XMLTV icons take priority over playlist logos; relative URLs resolve against the document, and image failures preserve row geometry.

The bundled Node `/api/epg` endpoint streams gzip/XML processing and selects metadata/programmes for requested channels. Bounds are a default ±24 hours, up to seven past days for archive channels, 384 programmes per channel, 50,000 total programmes, a 16 MB XML response and a 30-minute cache. Current/next/nearby programmes take priority when schedules are dense; truncation is disclosed. Requests contain channel identity metadata, not stream credentials or URLs. This fixed-CDN endpoint is separate from the general relay and requires the Node server; static hosting alone cannot provide it. Server-side `saxes` is not part of the TV runtime. See [EPG](docs/EPG.md).

Custom XMLTV feeds use direct XHR or the configured relay, whose gzip/deflate expansion has size limits. Visible current/next refreshes every 30 seconds; guide downloads refresh every 30 minutes and when overdue on foreground. A 4,096-entry lookup cache with a protected working set and rotating overflow reuses matched schedules/current-next until a programme boundary or guide change. Source changes, deletion and import release old guide references. Unchanged TV/favorites structure updates only changed EPG fields, retaining row, logo, preview, focus and description-scroll identity. Decorated channel catalogs and favorite order indexes avoid repeated sorting and quadratic membership work. Archive history beyond seven days requires a suitable custom feed. For old browsers that omit Origin, `/api/epg` accepts `X-OTT2-EPG: 1` only when Host matches the socket address and port; an explicit mismatched Origin is rejected. The general relay still requires Origin.

Cancellation and stale callbacks are covered for source/catalog/EPG loading and playback resolution. Changing/deleting a source clears catalog ancestry, nested results and previous EPG URLs. Old-session bookmarks cannot overwrite imported state.

### Playback and compatibility bootstrap

Native HTML5 video, Hls.js 1.7.3, Shaka Player 5.2.10 and mpegts.js 1.8.2 are bundled locally with licenses and provenance. The new core-js bootstrap installs missing language APIs before any media library. Native binary support is captured before polyfills so JavaScript-emulated typed arrays cannot incorrectly enable MSE.

The ordered page bootstrap is `compat.js` → `core-js.min.js` → `compat-ready.js` → application modules → interface start. Optional media libraries load only on demand after native capability checks, with shared in-flight requests, cancellation of stale callbacks and a five-second bound. Failed/timed-out libraries remain quarantined for the page session; late global assignments cannot replace accepted references. It supplies Promise, Symbol/iterators, collections, modern Object/Array/String/Number/Math methods, URL helpers and typed-array methods. Platform helpers preserve native/prefixed object URLs and provide a monotonic performance clock when absent. Existing working native implementations are retained where supported by the upstream polyfill feature tests.

HLS uses a same-origin Worker when native capabilities permit. Its independent realm imports the same compatibility bootstrap before the matching official HLS worker payload. Missing Worker support uses main-thread transmuxing; a reported asynchronous worker error disables workers for subsequent playback attempts in that player instance. Synchronous construction failures fall back inline through Hls.js and may be retried on later channels. MPEG-TS workers remain disabled. Native MSE, streaming network loaders, firmware bridges, hardware codecs and DRM are capability requirements, not simulated APIs. See [Engine compatibility](docs/ENGINE-COMPATIBILITY.md) and the [24 device profiles](docs/DEVICE-CONTRACTS.md).

Auto selects native HLS first on LG, a compatible MSE backend in Chromium, Shaka for DASH, mpegts.js for supported HTTP TS/FLV, and HTML5 for ordinary files. Format detection uses explicit settings, URL, then a bounded cancellable Content-Type/body probe. Failed detection is not a guessed format. Auto has bounded fallback among compatible engines; manual selection retains the requested backend.

Engine selection is available from the playback Engine button, Options, Settings and the remote yellow key. Engine and format preferences persist separately. Unavailable engines are identified. OSD shows preference, active backend, format and position. OK opens playback controls; Left/Right selects a control, OK activates it and Up/Down hides the strip. Engine changes preserve pause intent after releasing the previous session. VOD/archive uses seconds; live preserves distance behind the new live edge, including when an initial seek is temporarily rejected.

Playback includes loading/playing/buffering/retrying/paused/stopped/error states, at most three live retries, bounded stall detection, stale-event suppression and asynchronous teardown. Autoplay recovery requires a user gesture: the footer remains visible with Play focused, and the saved mute setting is retained. Confirmed playback restores the ordinary six-second footer deadline. Seeking respects duration/DVR ranges and gaps. Audio/subtitle selection, subtitle off, aspect/zoom, standard/WebKit PiP, fullscreen and Back depend on actual backend capabilities. Transmuxing changes containers, not unsupported codecs or CORS policies.

Input uses only a validated positive integer keyCode, or which when keyCode is unavailable, followed by the selected device profile. Modern key/code names never supply or override an action. All 24 profiles retain independent numeric maps. Return is navigation; a separate Exit exits fullscreen, cancels an open dialog or requests exit in windowed mode. Power exits immediately without confirmation. A shared Return/Exit code retains Return behavior, including Android code 4. Desktop fullscreen, Space, Tab, page navigation, keypad digits and multimedia codes are explicit additions to PC, PC2, NodeJS and Edem profiles. Maple 73 remains Stop, 33 remains Blue, and Android 9 remains digit 2. Focused EPG description scrolling uses profile navigation, including Android arrows 19–22. Desktop controls retain strict keyup tracking; remote profiles recover after a 350 ms quiet gap if keyup is absent. Repeats refresh the release timer, and keyup, blur and teardown clear it. The timeout is profile data and requires physical-device timing validation.

Desktop Q (81) exits immediately without an exit confirmation, including from fullscreen and non-editing dialogs. L toggles DOM fullscreen using the whole document so dialogs remain visible. Escape exits fullscreen without leaving playback; windowed Escape requests exit, while an existing dialog owns cancellation. Key-repeat suppression and a cancelled fullscreen-entry generation protect asynchronous transitions. Ctrl/Alt/Meta combinations and editable letter input are left intact. Remote Back and desktop Backspace retain browsing navigation. Direct Q/Power exit and confirmed Exit share cleanup: they save an available VOD bookmark, retain the remembered channel, cancel outstanding work, release media and attempt window closure; a stopped exit screen remains when the browser rejects closing the tab.

Playback startup, I/remote Info and a transparent bottom mouse area share a six-second information footer. The next I/background click expands the current EPG description and restarts the same timer; further activations retain expanded mode. Auto-hide also applies while paused, except while autoplay is blocked and Play must remain available. Current and archived programme metadata remain plain text, repeated media updates preserve text nodes and scroll position, and focused description arrows/page keys scroll without changing channels. Existing playback buttons keep their actions.

### Compatibility improvements in 0.5.0

Previous Channel now uses a separate source-bound reference to the previously confirmed live broadcast, rather than choosing the adjacent list item. It works across sources with source/playback PIN checks, survives reloads and follows the same conservative identity matching as startup restore. Failed tune attempts cannot replace the confirmed pair. Source removal and ordinary source-free exports clear these references.

Dedicated numeric Audio/Subtitle/Aspect/Zoom actions open playback options and PiP toggles the current session where supported. Existing profile collisions retain Stop/fullscreen priority. Transport/toggle repeats are suppressed even when old remotes omit `event.repeat`. Digits 0–9 seek to 0–90% for known-duration VOD/archive; live digits keep channel selection. Pagehide, beforeunload and hidden-document events flush available VOD bookmarks without duplicate writes.

Per-channel audio/subtitle and picture preferences are bounded to 200 recent, source-bound records. Language/label matching tolerates track order changes and rejects ambiguity; metadata-free numeric IDs only carry within the same backend. Explicit subtitle Off is reasserted when late tracks appear. Adapter generation changes reapply tracks without repeated selection during ordinary pause/resume. Live preferences may follow a uniquely matched provider identity after stream IDs rotate. Global picture settings remain defaults for uncustomized channels; ordinary exports exclude these source-bound records.

Auto handles silent startup, unchanged-clock stalls and positively established missing video. Radio and unknown manifests are not guessed to contain video. Native HLS master inspection has explicit size/time/cancellation bounds and requires successful HLS responses for codec evidence. Fresh decoded-frame counters are preferred, with weaker dimensions/TrackList hints on older firmware. HLS gets one media-error recovery/downshift per session and conservative TV buffers. See [the precise limits and evidence](docs/ENGINE-COMPATIBILITY.md).

The vendor builder reproduces all 11 JavaScript/license assets from pinned npm packages and verifies the lockfile, builder and output hashes. No device-side build is introduced. The healthy HLS Worker test requires actual init/transmux completion; the deliberate Worker HTTP failure separately verifies nonfatal main-thread decoding.

### PIN, import and relay

A 4–12 digit PIN uses salted iterated SHA-256 storage. Authorization expires and resets on reload, source change, lock or clock rollback; failed attempts impose a persisted cooldown. Playback, delayed resolution, resume, archive and protected descendants share one gate. Settings, sources, import and export have separate checks. Lock now stops protected playback. This is local parental control, not protection against a browser owner with storage/developer access.

Import recognizes the native schema, legacy v1 JSON, known storage keys and a restricted properties XML format. A preview precedes replacement. Plaintext legacy PINs are not imported; existing protection is retained. Ambiguous provider-local favorites/protection IDs require review rather than guessed identity. Imports requiring parental review keep startup restore disabled and mark the startup migration complete. DTDs/external entities are not loaded. Invalid imports leave settings unchanged. Ordinary export excludes source URLs, playlist bodies, EPG URLs and the remembered playback source reference.

The optional Node relay is disabled without an allowlist. It accepts same-origin JSON POST for upstream GET, checks exact origins and DNS with address pinning, rechecks redirects, filters headers and applies 64 KB request/16 MB response/20-second limits. Cookie/Authorization do not cross origins. Loopback is the default; LAN upstreams require explicit IP allowlisting. It relays source data, not media or remote-control commands.

## Remaining platform and ecosystem work

1. Physical TV/STB acceptance and proprietary AVPlay/OIPF/gSTB/webOS media bridges, system power/sleep, vendor DRM and installers remain separate implementation and device work. Input profiles do not establish decoder or firmware support.
2. The 48 historical provider names are documented, not claimed as 48 working adapters. Live operator accounts, modified portal contracts, the original FOSS JSON-RPC Stalker dialect, provider-specific archive/EPG and VPortal/fXML require separate work.
3. Cloud/dealer/account services, authenticated remote commands, the old Native HTTP bridge and auto-update are not connected. The documented public EPG fallback works independently of the original runtime/companion protocol.
4. The shipped UI supports English/Russian. Other cataloged languages and RTL remain specification extensions; project comments and documentation are English.
5. PiP uses the current media session where supported. An independent second-channel preview and mosaic are not implemented.

The original `ottplay-foss` is neither modified nor used as the application runtime. Physical playback/input/lifecycle verification remains distinct from browser and source checks.

## Local shared-core migration

The browser and Node guide filter now consume the same generated OttPlay
multiplatform core for XMLTV timestamps, normalized/canonical names, ordered
channel matching and current/next selection. The browser's cached schedule
window uses that selection too. Platform XML decoding, HTTP, feed indexes and
UI remain in this client. Archive URL decisions and M3U metadata parsing,
grouping, duplicate handling, archive availability and identity inputs now use
the same core. URL resolution and hashes remain injected host primitives;
non-M3U provider sessions and durable state still need migration. Browser M3U
inputs are bounded to 32 Mi UTF-16 code units, 1 Mi per line and 100,000 unique
